## Why this skill exists

React publishes **no** official guidance on project structure — the only statement the React team
ever made lives in the archived `legacy.reactjs.org` FAQ and react.dev has no successor page. Next.js
describes itself as "unopinionated about how you organize and colocate your project files". Structure
therefore cannot be looked up, only decided. This file is the audit trail for that decision.

The research behind it: five parallel research passes over official documentation, primary sources and
recognized experts, synthesized into `reports/Архитектура React и Next js.md` at the repo root, with
raw notes in `research_notes/Архитектура React и Next js/`.

## Scope boundary

Architecture and code organization only. Rendering performance, memoization, bundle size and Core
Web Vitals belong to the vendored `next-best-practices` and `react-best-practices` skills. This
separation is deliberate: those two skills were already installed, and a third skill repeating them
would just create conflicting advice.

**One conflict is known and resolved in `SKILL.md`:** `react-best-practices` says "Shared utilities
go in `utils/`", which this skill forbids. On placement and naming, this skill wins; on hooks, state
and rendering, `react-best-practices` wins.

## Decisions taken over documented disagreement

Five questions had no consensus in the sources. Each was resolved explicitly rather than by picking
whichever blog was read last. Approved by the repo owner on 2026-09-29.

| # | Question | Position taken | Why |
|---|---|---|---|
| 1 | Barrel files (`index.ts`) | **Facade yes, aggregator no.** A one-line re-export beside a component is allowed; multi-module barrels are confined to the design system. | The measured harm (cycles, tooling latency) is all about fan-out. A single-module facade is not actually in dispute — neither camp's evidence touches it. Matches the codebase: 57 `index.ts`, only 4 aggregating, all in `vendor/ui`. |
| 2 | Cross-feature coupling | **Lift it up, enforce with ESLint `import/no-restricted-paths`** (Bulletproof React's approach) rather than FSD's explicit cross-import notation. | The codebase is route-colocated with no feature folders at all. FSD's notation buys the same guarantee only after a full re-layering; the lint rule is one config. |
| 3 | Category-named folders | **Hybrid: ban `utils/` and `helpers/`, name modules by purpose; keep narrow category folders like `hooks/`.** | The ban is the best-supported part (Fowler, Cheney, FSD all argue against category naming) and the utils/helpers distinction is folklore. Full FSD segment vocabulary would mean renaming all of `src/lib` for no added guarantee. |
| 4 | Domain layer | **No domain layer.** Pure functions plus hooks; the Zod schema is the contract. | The client is a thin UI over an API that owns the business rules. Fowler's anemic-domain-model test cuts against most frontend implementations, and the advocates themselves call a full build overkill for most apps. The notes' own summary: *advocacy is better written, rejection is better adopted*. |
| 5 | Radix `asChild` vs Base UI `render` | **Not applicable.** | `client/src/vendor/ui` uses neither — no `asChild`, no `Slot`, no `render` prop. This is a library choice, not an architecture rule, so the skill carries only the underlying principle (composition over configuration). |

## Claims deliberately excluded

Carried forward from the research so they are not reintroduced later:

- **Dan Abramov's 2019 disclaimer** on "Presentational and Container Components" — substance is
  attested by multiple secondary sources, but `medium.com` returns HTTP 403 and archive routes are
  blocked, so no verbatim quotation could be obtained. Never quote it verbatim.
- **"Move files around until it feels right"** (Abramov) — the original tweet is deleted; only
  second-hand attribution survives.
- **A State of JS satisfaction statistic for Next.js** (reported as 68%→55%) — found only in one
  low-authority SEO blog. Unverified.
- **"The App Router is easy but not simple"**, attributed to Lee Robinson — no primary source found.
- **"Six RSC CVEs in two months"** — aggregator claim; only two were verified.
