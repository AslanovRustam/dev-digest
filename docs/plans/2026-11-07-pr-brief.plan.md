# Implementation Plan: PR Brief (L05)

## Summary for the caller
PR Brief on Overview: one checked, stored, staleness-aware model call over computed facts; clicks deep-link into Files changed.
- **shared (both copies)**: `PrBrief` reshaped to the spec contract + `PrBriefResponse`. No DB migration (SHA, review id, inputs in `pr_brief.json`).
- **server**: module `brief` (GET/POST `/pulls/:id/brief`); `container.blast` facade; `ProjectContextFacade.forBrief` (D-1); `call=brief` log; `brief.system.md`.
- **client**: hooks; card parts on Overview; IntentCard chips hidden under a brief; Files changed honours `?file=&line=`.
- **reviewer-core, mcp, e2e**: no change.

Sequence: GET → stored brief + `stale_reasons`, no model · POST → per-PR lock (409) → key check → parallel collect → `buildBriefInput` (caps, fences, ≤ 8,000) → `completeStructured` (maxRetries 1) → `checkAnswer` → upsert → one `call=brief` record.

### Requirements check — DEFAULTED
- RQ-1 AC-29 "keep only … risks whose path is in …" — risk left with no valid ref → dropped (user's decision, G-3).
- RQ-2 NFR-7 vs free-text reasons — default: `inputs[].reason` is a code enum shown via `brief.json`; blast detail code in `ref`.
- RQ-3 "newest review" — default: newest `reviews` row by `created_at` (as client `latestReview`); open = not dismissed.
- RQ-4 NFR-5 120 s — default: 2 × 50 s attempts inside a 115 s deadline; a late answer is discarded.
- RQ-5 NFR-3 — default: one record per generation that reached the model call; 404/409/429/config_error log none.
- RQ-6 AC-8 vs NFR-7 — default: own verdict line with `brief.json` strings, not `VerdictBanner`.
- RQ-7 — default: `setTab` drops `file`/`line` from the URL.
- Spec impact: none.
